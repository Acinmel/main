# UI Guide

## 产品气质

这是创作型 SaaS 工具，不是营销落地页。界面应以任务效率、状态清晰、信息密度和稳定反馈为优先。

设计关键词：

- 清晰
- 专业
- 高信息密度
- 稳定布局
- 可重复操作
- 明确进度

## 主要页面

| 页面 | 路由 | 目标 |
|---|---|---|
| Landing | `/` | 介绍核心能力并引导进入数字人或创作 |
| 数字人配置 | `/digital-human` | 上传自拍、选择风格、生成模板 |
| 资源库 | `/resources` | 管理头像、声音、字幕模板 |
| 创作工作台 | `/studio` | 主创作流程 |
| 任务流程 | `/tasks/:id/*` | 旧任务分步流程 |
| 后台 | `/admin/*` | 管理员数据、用户、资源、审计 |

## 布局规则

- 工具型页面优先使用顶部导航 + 内容区 + 右侧或下方操作区。
- 不嵌套卡片。卡片只用于重复项、表格容器、模态框或明确分组。
- 页面级 section 使用全宽带状或无边框布局。
- 控件区要固定尺寸或稳定网格，避免 hover、loading、错误提示造成布局跳动。
- 桌面端建议内容最大宽度 1180px 到 1440px，后台表格可全宽。
- 移动端优先单列，底部关键操作保持可触达。

## 组件规则

- 工具按钮优先图标按钮或图标 + 文本按钮。
- 二元配置使用 switch 或 checkbox。
- 多选项模式使用 segmented control、radio group 或 tabs。
- 数值配置使用 slider、stepper 或 input number。
- 状态使用 badge、tag、progress，不用长段解释文字。
- 文件上传必须展示文件名、大小、进度、失败原因。
- 长任务必须展示 pending、processing、success、failed。

## 文案规则

- 按钮文案使用动作词：`生成`、`上传`、`预览`、`保存`、`重试`。
- 错误提示说明可执行动作，例如“请检查 DY_DOWNLOADER_COOKIE 后重试”。
- 不在页面中展示开发说明、快捷键说明或实现细节。
- 复杂状态尽量用短标签和 tooltip。

## 响应式规则

必须检查：

- 375px 移动宽度。
- 768px 平板宽度。
- 1440px 桌面宽度。

移动端：

- 主内容单列。
- 表格改为卡片列表或横向滚动容器。
- 底部操作栏不遮挡表单。
- 长按钮文字允许换行，但不能溢出。

桌面端：

- 创作页可使用左右栏，预览区固定比例。
- 后台页面优先表格和筛选栏。
- 列表操作按钮保持右侧对齐。

## 状态设计

每个异步区块必须有：

- 初始态。
- 加载态。
- 成功态。
- 空态。
- 失败态。
- 重试入口。

长任务建议展示：

- 当前阶段名称。
- 进度百分比或轮询状态。
- 预计等待提示。
- 可取消时提供取消入口。

## 性能规则

- 路由页面使用懒加载。
- 大型列表必须分页、cursor 或虚拟列表。
- 轮询必须有间隔、上限、错误退避。
- 音视频预览释放 object URL。
- 上传进度回调不得高频触发昂贵渲染。
- 图片使用 webp 或压缩后的预览图。

## Naive UI 使用规则

- 表单：`n-form`、`n-input`、`n-select`、`n-upload`。
- 数据：`n-data-table`、`n-pagination`、`n-empty`。
- 状态：`n-tag`、`n-progress`、`n-alert`。
- 反馈：`n-message`、`n-notification`、`n-modal`、`n-dialog`。
- 后台表格批量操作要有确认弹窗。

## 前端 Agent 交付前检查

```bash
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

浏览器检查：

- 控制台无新的 error。
- API 失败时 UI 有提示。
- 上传、生成、轮询、下载流程可以完成或明确失败。
- 375px 与 1440px 下无明显重叠和溢出。
